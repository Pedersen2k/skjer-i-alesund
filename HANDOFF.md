## Goal
A public website listing what's on in Ålesund (concerts, standup, shows, kids' events, clubs, happenings, AaFK home matches), with ticket prices, that updates itself every day.

**Live:** https://kaskjerda.no/ (the old https://pedersen2k.github.io/skjer-i-alesund/ redirects there)
**Repo:** https://github.com/Pedersen2k/skjer-i-alesund (owner: Pedersen2k)

## Current state

- The page has these features:
  - Filters for time, category, venue and price, plus search.

  - Search engine support: schema.org `Event` JSON-LD, built in `index.html` from `events.json`, and `sitemap.xml`. The site is added to Google Search Console (verification meta tag in `index.html`, sitemap submitted).
  - Static subpages from `scripts/pages.py` (built at every deploy into `_site/`, which is what Pages publishes): `i-dag/`, `denne-helgen/`, one per category (`konserter/`, `standup/`, `show/`, `barn-og-familie/`, `klubb/`, `happenings/`, `aafk-hjemmekamper/`), `scene/<venue>/` for venues with 3+ events, and `arrangement/<id>/` per event, each with its own title, description and JSON-LD. `sitemap.xml` (all of them) and `404.html` are generated too. "Del" on the front page now links to the event page, so shared links get a proper preview.
  - A weekly "Helgepost": every Thursday `.github/workflows/helgepost.yml` opens an issue (emails the owner) with ready-to-paste Facebook and Instagram text for the coming weekend, closing last week's. The Instagram image (`denne-helgen/helgen.png`, 1080×1350, Pillow + Bricolage/Figtree fonts downloaded in the workflow, DejaVu fallback) is built by `pages.py` at every deploy and is also the `og:image` for `denne-helgen/`. If the large layout can't fit everything it switches to one-line rows, and spills over to `helgen-2.png` etc. (an Instagram carousel); the issue shows all images.
  - Repeated shows now carry `moreShows` (later start times) in `events.json`, so "I dag", "Denne helgen" and the weekly post include a show on every day it plays. The front page's date filters still only use the first date.
  - A logo (a jugendstil gable above a wave), also used as the favicon and for link previews (`og-image.png`).
- GitHub Actions runs twice a day, at about 06:50 and 20:50 Norway time (winter time; one hour later in summer). It fetches the latest events and commits `data/events.json`. If anything changed, it redeploys Pages.
- If a run fails or returns warnings, the workflow opens a GitHub issue, which emails the owner. The issue is closed automatically once a later run succeeds.
- Alert and Helgepost issues are assigned to the repo owner (`--assignee "$GITHUB_REPOSITORY_OWNER"`). Issues opened by the Actions bot only email people watching the repo; assignment makes GitHub email the owner. Confirmed working on 22 Oct (issue #12).

## Key decisions
- **Static site + GitHub Pages + Actions.** It's free, and visitors don't need to log in. An earlier version was a Claude artifact backed by a database, but only signed-in Claude users could see its data. The daily Claude task that updated it (`trig_01UEPBzcKQrHz5XpXGLXK7qc`) is **disabled, not deleted**. That artifact (https://claude.ai/artifact/GqCPeYEgqsrcpUir5M7FHj) is no longer updated.
- **Data comes from the organisers' own pages, not from search.** Automatic sources: Tikkio, Parken, AaFK, Dampsentralen, O'Connor's, Viti and Fabrikken Kulturscene; everything else is in `manual.json` with a source link. Sites that block automated requests (Billetto, strawberry.no) are not worked around: the owner pastes the page text instead.
  - Tikkio event pages list every ticket type with its price.
  - The "price" field in Tikkio's listing is often `0.00`, which means unknown, not free.
  - The shown price is the ordinary ticket. Up to two discounts go in the note.
- **Repeated performances are merged into one card**, for example the Løvenvold Christmas show, which has 20+ dates. The other dates and times go in the note.
- **Nothing is invented.** Events, dates and prices come only from a source. When sources disagree, the event gets `uncertain: true` and an explanation in the note.
- Ticketmaster and Eventim were considered and not used. Almost all Ålesund events are sold on Tikkio. TicketCo is only used by AaFK, and its prices are not fetched.
- **AaFK matches are included** as category `sport`. `fetch_aafk()` in `sync.py` reads the schedule pages on aafk.no (men's and women's) and keeps only matches at Color Line Stadion. The page layout (`tr.schedule__match`) is a scraping target: if aafk.no changes it, the workflow opens an issue.
- **Sjøborg is dropped.** It is in Ulsteinvik, not Ålesund.

## Key files
| File | Purpose |
|---|---|
| `index.html` | The entire site (HTML/CSS/JS). Reads `data/events.json`. |
| `scripts/sync.py` | Fetches Tikkio, Parken, AaFK, Dampsentralen, O'Connor's, Viti and Fabrikken, merges repeated shows, applies overrides, adds `manual.json` (with `roll_forward()`), and writes `data/events.json`. |

| `docs/` | Interactive design mockups the owner chose from (not published). |
| `data/overrides.json` | Per-event fixes to category, title, time or note. The key is the normalized title slug. |
| `.github/workflows/oppdater.yml` | Daily sync, commit, Pages deploy, and failure alerts. |
| `scripts/pages.py` | Builds `_site/`: the front page plus static subpages, `sitemap.xml` and `404.html`. Run on every deploy. |
| `scripts/helgepost.py` | Weekly post text (for the Helgepost issue) and the weekend image. |
| `.github/workflows/helgepost.yml` | Thursday Helgepost issue. Can also be run by hand. |
| `scripts/artifact_preview.py` | Builds a preview of the site that can be published as a Claude artifact. |

## Theme "kveld" (26 Oct, live as the default for everyone)
`tema-kveld.css` (copied to `_site/` by `pages.py`) is a dark "Kveldsstemning" theme, scoped to `html[data-tema="kveld"]`. A small inline script in `<head>` (in `index.html` and `page()` in `pages.py`) turns it on for everyone unless the visitor has chosen the old design: `?tema=standard` stores `skjer-tema=standard` in localStorage (light design), `?tema=kveld` switches back. A switch "Mørkt | Lyst" (`.tsw`, top right on the front page; in the crumbs row on subpages made by `page()`) stores the choice in localStorage (`skjer-tema`; "Lyst" also sets `skjer-theme` to light) and reloads, so no `?tema=` is needed (the loader still understands it and removes it from the URL). The old light/dark toggle and the footer links are gone; "Lyst" is the old design forced to light. Raw pages (kino, etc.) have no switch yet. The owner liked it and wants to try it as the default for a few days (decision 26 Oct). **To go back to the old design for everyone:** in the loader change `!=="standard"` to `==="kveld"` (opt-in again) in both places, or revert the PR. Mockups: `docs/design-forslag.html` (six designs; D chosen), `docs/tema-d.css` (preview overlay). Not yet tested on a real phone; check contrast of small grey text outdoors. B (skyline illustration) could be combined with D.

## Gotchas
- The Claude cloud environment blocks `*.github.io`. Claude can't open the live site, so test locally: `python3 -m http.server`.
- `www.` domains must be allowlisted separately in the environment's network settings.
- Hosts such as `aafk.ticketco.events` must be allowed in the environment's network settings; a change may need a new session to apply.
- The bot commits every day, so run `git pull` before pushing.
- Merging to `main` triggers the deploy workflow. If its last step ("deploy-pages") fails with a Pages error, it is usually transient: re-run the failed job once (Actions → Re-run failed jobs).
- Playwright is not installed in the environment. A working local check: `npm i playwright-core` in a scratch folder and launch `executablePath: '/opt/pw-browsers/chromium'` against `python3 -m http.server -d _site`. Rebuilding `_site/` deletes the folder, so restart the server afterwards.

## Viti as a source (26 Oct)
`fetch_viti()` in `sync.py` reads `https://www.vitimusea.no/arrangement` and each event page. The pages are Next.js: dates (UTC, converted to Europe/Oslo), city (`selectCity`) and museum (`selectMuseumArray`) come from the structured data in `self.__next_f`; the price is read from the free-text block (`Pris:` / `Inngang:`) by `viti_price()` and the rest of that line goes into the note. Only events in Ålesund are kept (Jugendstilsenteret og KUBE, Sunnmøre museum; Anders Svor-museet is in Hornindal, Naturmuseet and Møbelmuseet in Sykkylven). Events that span several days (umbrella entries like "Familiedager på museet") are skipped. Category: `barn` for family/baby events, otherwise `happening` (a raw `cat` is now supported in `build_events`). If the page can't be read, the old Viti events are kept and a warning issue is opened. Caveat: the free-text price differs per event, so events without a readable price show "Pris hos arrangør".

## Fabrikken Kulturscene as a source (26 Oct)
Owner decided: include everything Fabrikken Kulturscene (Molovegen, Ålesund) offers. `fetch_fabrikken()` in `sync.py` reads `https://www.fabrikkenkulturscene.no/program` (Webflow; each `role="listitem"` has the date as `dd.mm.yy` in `.card-date`, the title in `h3` and a Billetto ticket link) and each event page for the start time (the first "konsertstart/showstart/starter/Forestilling" time; the door time goes in the note) and a price (`Pris: 1350,-` via `viti_price()`, only the julebord has one). Titles drop " // Onsdag 18. november"-style parts (`fabrikken_title()`); the shouting caps are fixed per event in `overrides.json`, and so are categories (julebord = `julebord`, Karsten Blomvik = `standup`, Kontrabass og lyrikk = `show`). The 10 julebord evenings merge into one card with `moreShows`. `url` is the Billetto page. No address (Billetto says Molovegen 20, Fjord Norway says 22; not shown). If the page can't be read, the old Fabrikken events are kept and a warning issue is opened. Billetto itself (prices for the other events) is not read: its CloudFront blocks some user agents, and Claude's environment refused trying around that, so prices there would need permission or an API key (Billetto has an API with access keys). New events at Fabrikken get new titles that may need caps fixes in `overrides.json`.

## Julebord (26 Oct, live)
**What and why.** Julebord anyone can book (also couples and small groups), not private rooms or packages for big groups. The owner first wanted a category, then decided (to avoid clutter) that julebord should live on their own page like the cinema: design D + A from `docs/julebord-forslag.html` (also a private Claude artifact).

**How it works.**
- Category `julebord` (colour `--c-julebord`, red). `guess_cat()` in `sync.py` gives it to titles with julebord/julebuffet/julegilde; overrides set it for `julebord-pa-fabrikken` and `christmas-party` (Dampsentralen).
- Kept OUT of: the front-page list, category chips and dropdown, calendar view, "I dag", "I morgen", "Denne uka", "Denne helgen", month and venue pages, `kalender/alle.ics` and the Helgepost (`SEPARATE` in `pages.py`; `JB`/`E` split in `index.html`; filter in `helgepost.main()`).
- Shown on: `julebord/` (category page with `julemeny_html()` as lead: the restaurant box from `data/julebord.json`, then a "Tips oss" link, then the julebord by date), `jul-i-alesund/`, each event page (link "Alle julebord" instead of "Se i hele programmet"), `kalender/julebord.ics`, and the "Mer fra programmet" nav.
- Front-page entry, `julebordEntry()` in `index.html`: from 1 Nov to 26 Dec a second button in the Jul i Ålesund card (`#jbbtn`, "🎄 12 julebord · fra 625 kr"); before that (October) a strip under the cinema strip (`#jbstrip`). Count and lowest price come from the data. `?jul=1` or `#jul` forces the Christmas state (the hash is needed in Claude artifacts). GoatCounter events: `julebord/stripe`, `julebord/julekort`.
- Repeated julebord carry `moreShows`; `roll_forward()` in `sync.py` moves a manual event to its next date once the first has passed (before, manual events with several dates disappeared after the first one).
